# 从零开始：让 WorkBuddy 每天自动签到 + 派猫猫旅行

> 全程在网页上点鼠标，**不需要输入任何命令，也不需要懂 git**。

---

## 总览

| 步骤 | 花多久 | 干什么 |
|---|---|---|
| 第一步 | 5 分钟 | 注册 GitHub 账号 |
| 第二步 | 1 分钟 | 建一个私有仓库 |
| 第三步 | 5 分钟 | 在仓库里建 2 个文件 |
| 第四步 | 2 分钟 | 导出本机凭证，填进仓库 |
| 第五步 | 2 分钟 | 手动跑一次，确认成功 |
| 第六步 | — | 完成，以后每天自动跑 |

总共约 15 分钟。

## 这个文件夹里的文件分别干什么

| 文件 | 要上传到 GitHub 吗 | 用途 |
|---|---|---|
| `wb-daily.mjs` | **要**（放仓库根目录） | 云端每天执行的脚本 |
| `daily.yml` | **要**（放到 `.github/workflows/daily.yml`） | 定时任务配置 |
| `export-credential.cmd` | 不要 | 双击它，导出本机登录凭证 |
| `export-credential.cjs` | 不要 | 上面那个的配套文件，别单独删 |
| `如何部署.md` | 不要 | 就是本文 |
| `refresh-token.txt` | **绝对不要** | 导出的明文凭证（填完可以删） |
| `credentials.env` | **绝对不要** | 同上 |

> 上传时只需要管前两个。其余留在本机。

## 第一步：注册 GitHub 账号

已经有了就跳过。

1. 浏览器打开 <https://github.com/signup>
2. 依次填：邮箱 → 密码 → 用户名（英文或数字，这就是你以后的账号名）
3. 邮箱会收到验证码，填进去
4. 如果问 "How many team members…"，随便选 Free / Just me 都可以

**完成标志**：进入 github.com 首页，右上角有你的头像。

> GitHub 界面是英文的。下面每个按钮我都给了英文原名，照着找就行。

---

## 第二步：新建一个仓库

1. 打开 <https://github.com/new>
2. **Repository name**（仓库名）填：`workbuddy-daily`
3. **Description** 留空即可
4. 选 **Private**（私密）—— 这一项很重要，原因见下方
5. 下面的 "Add a README file" 等复选框**一个都不要勾**
6. 点绿色按钮 **Create repository**

**完成标志**：跳到一个标题为 "Quick setup" 的空仓库页面。

> **为什么必须选 Private**：GitHub 官方规定「**公开**仓库 60 天内没有任何活动，会自动停用定时任务」。选私密仓库就不受这条约束。

---

## 第三步：在仓库里建 2 个文件

### 3.1 建 `wb-daily.mjs`

1. 在仓库页面点右侧的 **Add file** → 选 **Create new file**
2. 顶部有个文件名输入框，填：`wb-daily.mjs`
3. 在本机用**记事本**打开这个文件夹里的 `wb-daily.mjs`，按 **Ctrl+A 全选**，再 **Ctrl+C 复制**
4. 回到网页，粘到中间的大输入框里（**Ctrl+V**）
5. 点右上角绿色按钮 **Commit changes…** → 弹出的对话框里再点一次 **Commit changes**

**完成标志**：仓库首页出现 `wb-daily.mjs` 这个文件。

> 粘贴进去的内容很长（六百多行），这是正常的。

### 3.2 建 `.github/workflows/daily.yml`

这一步的路径是 GitHub 规定的定时任务位置，**必须一字不差**。

1. 回到仓库首页（点左上角的仓库名）
2. 再点 **Add file** → **Create new file**
3. 在文件名框里输入：

   ```
   .github/workflows/daily.yml
   ```

   输入过程中会看到提示 "Daily.yml is in a folder named `.github/workflows`" —— 这是对的，说明路径没错。
4. 用记事本打开本文件夹里的 `daily.yml`，**Ctrl+A → Ctrl+C**，粘到网页输入框
5. 点 **Commit changes…** → **Commit changes**

**完成标志**：仓库首页出现一个 `.github` 文件夹。

---

## 第四步：导出登录凭证，填进仓库

云端需要一把「钥匙」才能代表你去签到。这把钥匙就是你电脑上的登录状态。

### 4.1 在电脑上导出

1. 打开这个文件夹
2. **双击 `export-credential.cmd`**
3. 弹出黑色窗口，等几秒钟，看到「**凭证导出成功**」
4. 这时凭证**已经自动复制到剪贴板**了，不需要你手动复制
5. 按任意键关闭窗口

**完成标志**：窗口里显示 `已复制到剪贴板：是`。

> **如果提示「没有自动找到 WorkBuddy.exe」**：
> 右键桌面上的 WorkBuddy 图标 → 选 **打开文件所在位置** → 把那里的 `WorkBuddy.exe`
> **拖到这个 `export-credential.cmd` 文件上松手**。拖这一次就够了。

### 4.2 填进 GitHub

1. 回到你的仓库页面
2. 点右上区域的 **Settings**（设置）
3. 左侧菜单往下找 **Secrets and variables**，点它下面的 **Actions**
4. 点右侧绿色按钮 **New repository secret**
5. **Name** 框填：`WB_REFRESH_TOKEN`
6. **Secret** 框：直接按 **Ctrl+V**（凭证已经在剪贴板里）
7. 点 **Add secret**

**完成标志**：列表里出现一条 `WB_REFRESH_TOKEN`，更新时间是刚刚。

> 只需要填这一个。`WB_USER_ID` 之类的都不需要。

---

## 第五步：手动跑一次，确认成功

1. 点仓库顶部菜单的 **Actions**
2. 如果出现绿色按钮 **I understand my workflows, go ahead and enable them**，点它（没出现就直接下一步）
3. 左侧列表点 **WorkBuddy 每日签到**
4. 右侧有 **Run workflow** 下拉按钮，点开
5. 分支保持 `main`，**不要**勾 dry_run
6. 点绿色的 **Run workflow**
7. 等几秒刷新页面，会出现一条运行记录，点进去
8. 点左侧 **daily** 这个任务 → 展开 **执行每日任务** 这一步，就能看到日志

**成功的样子**（日志末尾会有这段）：

```
------------------------- 结论 -------------------------
签到：成功 — 今天已经签到过（连续 5 天），无需重复领取
派猫出行：成功 — 猫猫正在旅途中，不重复派出
--------------------------------------------------------
```

看到「签到：成功」就算成功了。

---

## 第六步：完成

到这里就结束了。以后每天北京时间早上 9 点多，它会自动完成这四件事：

1. 刷新登录状态
2. 签到领积分
3. 领掉猫猫已经到家的旅行积分
4. 判断今天是否已经派过 —— 没派过就派新的一趟

你不需要做任何事。

## 以后会遇到的正常现象

**定时任务比 9:23 晚十几分钟才跑**
正常。GitHub 免费调度器不保证精确时间。

**日志里写着「今天已经签到过」**
正常。要么是你今天已经在客户端手动签过了，要么这是今天的第二次运行。这不算失败。

**日志里有一行「未回写 Secret：未配置 GH_SECRETS_PAT」**
正常，忽略即可。登录凭证每次刷新都会换新的，脚本会把新凭证存在 Actions 的缓存里，下次自动接着用。详情见下面的「凭证会自动续期」。

**某天日志里出现「刷新登录态失败」**
说明钥匙过期了（大概每两个月会遇到一次）。重新做一遍第四步就行：双击 `export-credential.cmd`，然后到 Settings 里把 `WB_REFRESH_TOKEN` 更新一下。

## 常见问题

**Q：会不会影响我电脑上客户端的使用？**
不会。旧凭证在服务端有一段时间的复用宽限，我们实测反复刷新之后，桌面端登录状态依然正常。

**Q：明文凭证会不会泄露？**
不会进仓库、不会进日志。日志里凭证一律显示成 `<已隐藏 长度1530>`。你本机那个 `refresh-token.txt` 是明文的，填完 Secret 后可以删掉。

**Q：凭证会自动续期吗？**
会。每天运行时如果登录凭证被刷新了，脚本会把新凭证存进 Actions 缓存，下一次直接接着用 —— 所以你不需要定期维护。万一 GitHub 把缓存清理掉了（很少见），日志会提示你重新导出一次。

**Q：想改时间怎么办？**
编辑仓库里的 `.github/workflows/daily.yml`，把 `cron: "23 1 * * *"` 改成你要的。
它用 **UTC** 时间，北京时间 = UTC + 8。想改成北京时间 21:00，就写 `cron: "0 13 * * *"`。

**Q：想手动补跑一次？**
Actions → WorkBuddy 每日签到 → Run workflow。如果今天已经派过猫，它会自动跳过，不会重复派。

**Q：怎么停掉？**
Actions → WorkBuddy 每日签到 → 右侧 `…` → Disable workflow。想彻底清掉就把仓库删了。

## 出错了怎么求助

把这两样发出去就行：

1. Actions 日志里 **执行每日任务** 那一步的完整内容
2. 双击 `export-credential.cmd` 时那个黑窗口的截图

日志里不会有明文凭证，可以放心发。
